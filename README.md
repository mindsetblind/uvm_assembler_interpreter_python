# Ассемблер и интерпретатор УВМ (вариант 29)

Практическая работа №3 по дисциплине «Конфигурационное управление».

## 1. Общее описание

Проект реализует ассемблер и интерпретатор учебной виртуальной машины
(УВМ) — стековой машины с объединённой памятью команд и данных.
Язык реализации — Python 3.10+, внешних зависимостей нет.

Текущее состояние: **этап 2** — разбор текста программы в IR,
формирование машинного кода и запись бинарного файла.
Интерпретатор будет реализован на следующих этапах.

Этап 1 сохранён в ветке `stage-1`, этап 2 — в `stage-2`.

### Спецификация УВМ

Все команды имеют размер 5 байт. Поле A (код операции) — биты 0–5,
поле B начинается с бита 6.

Машинное слово формируется как `A | (B << 6)` и сохраняется в пяти
байтах little-endian (младший байт первым). Для записи памяти B отсутствует
и принимается равным нулю. Все неиспользуемые биты нулевые.
Команды следуют подряд без заголовка и разделителей; размер бинарного
файла равен числу команд, умноженному на 5.

| Команда           | A  | Поле B               | Семантика                                     |
|-------------------|----|----------------------|-----------------------------------------------|
| Загрузка константы | 38 | биты 6–31: константа | `push(B)`                                     |
| Чтение из памяти  | 63 | биты 6–18: смещение  | `addr = pop(); push(mem[addr + B])`           |
| Запись в память   | 62 | —                    | `value = pop(); addr = pop(); mem[addr] = value` |
| `pow()`           | 14 | биты 6–36: адрес     | `x = pop(); y = pop(); mem[B] = pow(x, y)`    |

Тесты из спецификации:

| Команда | Поля           | Байты                          |
|---------|----------------|--------------------------------|
| const   | A=38, B=439    | `0xE6, 0x6D, 0x00, 0x00, 0x00` |
| read    | A=63, B=201    | `0x7F, 0x32, 0x00, 0x00, 0x00` |
| write   | A=62           | `0x3E, 0x00, 0x00, 0x00, 0x00` |
| pow     | A=14, B=782    | `0x8E, 0xC3, 0x00, 0x00, 0x00` |

## 2. Язык ассемблера

Синтаксис «алгебраический» — в стиле Python. Одна команда на строке,
`;` в конце строки необязательна, комментарии начинаются с `#`.
Пробелы внутри команды игнорируются. Числа записываются в десятичной
(`782`) или шестнадцатеричной (`0x30E`) форме.
Ведущие нули в десятичном числе допустимы: `0439` означает `439`.
Значения поля B — неотрицательные целые в пределах ширины поля команды.

`pop()` — снятие элемента с вершины стека, `push(x)` — помещение
элемента на стек, `mem[x]` — ячейка памяти по адресу `x`.

| Запись                         | Команда            | IR                    |
|--------------------------------|--------------------|-----------------------|
| `push(N)`                      | загрузка константы | `load_const A=38, B=N` |
| `push(mem[pop() + N])`         | чтение из памяти   | `read_mem A=63, B=N`  |
| `push(mem[pop()])`             | чтение, смещение 0 | `read_mem A=63, B=0`  |
| `mem[pop()] = pop()`           | запись в память    | `write_mem A=62`      |
| `mem[N] = pow(pop(), pop())`   | `pow()`            | `pow A=14, B=N`       |

Порядок снятия операндов совпадает с порядком вычисления в Python:

* в `mem[pop()] = pop()` сначала вычисляется правая часть — первым
  снимается **значение**, затем **адрес**. Поэтому перед записью
  на стек кладут сначала адрес, затем значение;
* в `pow(pop(), pop())` аргументы вычисляются слева направо: первый
  снятый элемент — основание, второй — показатель степени.

Пример — записать `5 ** 3` по адресу 100:

```
push(3)                       # показатель степени
push(5)                       # основание
mem[100] = pow(pop(), pop())  # mem[100] = 125
```

Ассемблер проверяет, что значение поля B помещается в отведённое число
бит, и сообщает номер строки при ошибке.

## 3. Структура проекта и функции

```
src/uvm/spec.py        описание команд УВМ (коды, ширина полей)
src/uvm/assembler.py   ассемблер: текст -> IR -> машинный код, CLI
programs/              примеры программ на языке ассемблера
tests/                 модульные и интеграционные тесты (unittest)
run.sh                 скрипт запуска
```

Функции и классы `uvm.assembler`:

* `AssemblyError(line_no, message)` — ошибка исходника с номером строки;
* `Instruction(name, a, b, line_no)` — неизменяемая запись команды;
  `fields()` возвращает строку полей `A=.., B=..` (без B для записи памяти);
* `parse_number(text)` — читает десятичное или шестнадцатеричное число;
* `normalize(line)` — удаляет комментарий, пробелы и завершающий `;`;
* `parse_program(text)` — транслирует текст программы в список
  `Instruction(name, a, b, line_no)`;
* `parse_line(code, line_no)` — разбирает нормализованную строку,
  проверяет границы поля B и сообщает об ошибке через `AssemblyError`;
* `format_ir(program)` — форматирует IR в виде полей `A=.., B=..`;
  сохранён как вспомогательная функция этапа 1;
* `encode_instruction(instruction)` — преобразует проверенную команду IR
  в пять байт little-endian;
* `encode_program(program)` — соединяет машинный код проверенных команд;
* `format_bytes(data)` — выводит байты как `0xNN`, через запятые,
  по пять байт на строку;
* `build_arg_parser()` — создаёт парсер аргументов CLI;
* `main(argv)` — точка входа CLI.

Модуль `uvm.spec`:

* `CommandSpec(name, opcode, b_bits)` — описание команды;
  свойство `has_b` показывает наличие B, `b_max` задаёт его верхнюю границу;
* `COMMAND_SIZE`, `OPCODE_BITS`, `B_SHIFT` — размер команды, ширина A
  и начальный бит B;
* `LOAD_CONST`, `READ_MEM`, `WRITE_MEM`, `POW` — спецификации команд;
* `COMMANDS`, `BY_NAME`, `BY_OPCODE` — набор команд и словари поиска.

### Аргументы командной строки ассемблера

```
./run.sh asm <source.asm> <output.bin> [-t|--test]
```

* `source.asm` — путь к исходному файлу с текстом программы;
* `output.bin` — путь к двоичному файлу-результату;
* `-t`, `--test` — режим тестирования: вывод машинных байтов.

В обоих режимах создаётся бинарный файл и выводится число команд.
Существующий выходной файл перезаписывается после успешного разбора;
родительская папка результата должна существовать. Пустая программа
создаёт пустой файл и выводит ноль команд. Исходник читается в UTF-8.
Код завершения: `0` — успех, `1` — ошибка чтения, разбора исходника
или записи результата, `2` — ошибка аргументов CLI.
`./run.sh` без команды или с неизвестной командой выводит подсказку
и завершается с кодом `2`. Дополнительных настроек нет.

## 4. Сборка и тесты

Сборка не требуется. Запуск тестов:

```
./run.sh test
```

Тесты проверяют IR, точные байты из PDF, нулевые и максимальные значения
полей, порядок команд, создание бинарного файла, тестовый вывод и ошибки
CLI. Бинарные результаты создаются во временных папках и не попадают в Git.

## 5. Примеры использования

Программа с тестами из спецификации — `programs/spec_tests.asm`:

```
./run.sh asm programs/spec_tests.asm out.bin --test
```

Вывод:

```
Ассемблировано команд: 4
0xE6, 0x6D, 0x00, 0x00, 0x00
0x7F, 0x32, 0x00, 0x00, 0x00
0x3E, 0x00, 0x00, 0x00, 0x00
0x8E, 0xC3, 0x00, 0x00, 0x00
```

Файл `out.bin` содержит ровно 20 байт, совпадающих с этими строками.
Обычная сборка без показа байтов:

```
./run.sh asm programs/spec_tests.asm out.bin
```

Вывод: `Ассемблировано команд: 4`. Результат в файле тот же.
Эта программа предназначена для проверки кодирования команд, а не для
исполнения: она не подготавливает стек и память для всех операций.
